═══════════════════════════════════════
CONSTRUCTOR PURPOSE

```dart
FirebaseAuthRepository({
  FirebaseAuth? firebaseAuth,
  GoogleSignIn? googleSignIn,
})  : _firebaseAuth = firebaseAuth ?? FirebaseAuth.instance,

```

Purpose:

Meaning:

- otherwise use default SDK instance

═══════════════════════════════════════
WHAT DOES THIS MEAN?
═══════════════════════════════════════

```dart
FirebaseAuth? firebaseAuth
```

means:
optional FirebaseAuth object may be passed from OUTSIDE.

Currently:
nobody passes it.

So:
firebaseAuth == null

═══════════════════════════════════════
THEN THIS RUNS:
═══════════════════════════════════════

```dart
firebaseAuth ?? FirebaseAuth.instance
```

Meaning:

IF firebaseAuth exists:
    use it

ELSE:
    use FirebaseAuth.instance

═══════════════════════════════════════
WHAT IS ??
═══════════════════════════════════════

Null-coalescing operator.

Example:

```dart
name ?? "Guest"
```

Meaning:

IF name exists:
    use name

ELSE:
    use "Guest"

═══════════════════════════════════════
WHAT IS FirebaseAuth.instance?
═══════════════════════════════════════

Global singleton Firebase auth manager.

Provided by Firebase SDK internally.

═══════════════════════════════════════
WHY ALLOW CUSTOM OBJECTS?
═══════════════════════════════════════

For:
- testing
- fake auth
- mock auth
- special environments

Example:

```dart
FirebaseAuthRepository(
  firebaseAuth: fakeFirebaseAuth,
)
```

VERY important production engineering concept.

Used for:

═══════════════════════════════════════
STREAM EXPLANATION
═══════════════════════════════════════

Future:
ONE value ONCE.

Example:
```dart
Future<String>
```

returns:
"Gokul"

once.

DONE.

═══════════════════════════════════════

Stream:
continuous updates over time.

Example:

```dart
Stream<int>
```

can emit:

1
2
3
4
5
...

continuously.

═══════════════════════════════════════
REAL WORLD ANALOGY
═══════════════════════════════════════

Think:
YouTube live chat.

Messages continuously arrive.

That is stream behavior.

═══════════════════════════════════════
FIREBASE AUTH STREAM
═══════════════════════════════════════

Firebase continuously watches:

"Is user logged in or not?"

Whenever auth state changes:
- login
- logout
- session restore

Firebase emits new values automatically.

Example:

App starts:
→ null emitted

User logs in:
→ User object emitted

User logs out:
→ null emitted again

═══════════════════════════════════════
WHY THIS IS POWERFUL
═══════════════════════════════════════

UI automatically updates.

No manual refresh required.

signInWithGoogle()
═══════════════════════════════════════

FULL FLOW:

1. opens Google account picker
2. Google authenticates user
3. Google generates tokens
4. app receives tokens
5. Firebase verifies tokens
6. Firebase creates session
7. UserEntity returned

═══════════════════════════════════════
GOOGLE LOGIN FLOW DETAILED
═══════════════════════════════════════

```dart
final googleUser = await _googleSignIn.signIn();
```

Google SDK:
- opens account picker
- authenticates user

═══════════════════════════════════════

```dart
final googleAuth = await googleUser.authentication;
```

retrieves:
- access token
- ID token

═══════════════════════════════════════
WHAT ARE TOKENS?
═══════════════════════════════════════

Tokens are secure digital proof.

═══════════════════════════════════════
ACCESS TOKEN
═══════════════════════════════════════

Think:
temporary permission pass.

Used for:
- accessing Google APIs
- temporary authorization

Short-lived.

═══════════════════════════════════════
ID TOKEN
═══════════════════════════════════════

Think:
digital identity proof.

Tells Firebase:
"This user authenticated successfully with Google."

Firebase cryptographically verifies it.

═══════════════════════════════════════
WHERE TOKENS ARE GENERATED
═══════════════════════════════════════

Generated by:
✅ Google servers

NOT our app.

FLOW:

User logs into Google
↓
Google validates login
↓
Google generates tokens
↓
SDK returns tokens to app

═══════════════════════════════════════
REFRESH TOKEN
═══════════════════════════════════════

Problem:
access tokens expire quickly.

Solution:
Firebase internally stores:
✅ refresh token

Think:
long-term renewal key.

When access token expires:
refresh token automatically gets new access token.

WITHOUT user logging in again.

═══════════════════════════════════════
IMPORTANT
═══════════════════════════════════════

Refresh token is:
❌ NOT visible in our code

Firebase SDK manages it internally securely.

═══════════════════════════════════════
FULL FIREBASE LOGIN FLOW
═══════════════════════════════════════

User logs into Google
↓
Google generates tokens
↓
App receives tokens
↓
GoogleAuthProvider creates Firebase credential
↓
Firebase verifies tokens
↓
Firebase creates session
↓
Firebase stores refresh token securely
↓
User authenticated
